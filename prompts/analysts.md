# Prompt · 三个分析任务（风险审计 / 薪资推荐 / 简历改写）

---

## 一、风险审计 → `04_简历风险点.md`

### 输入
`resume.json`、`jd.json`、`evidence.json`（可选）、`rubric/red_flags.md`

### 任务
逐条扫描简历，找出**会被面试官当场问倒或戳穿**的地方。

### 输出格式

```markdown
## R-01 ｜ 🔴 一票否决 ｜ 可验证
- **类型**：张冠李戴（M-01）
- **原文**："设计并实现基于 Binlog + Kafka 的实时数据同步链路，将 Oracle 数据实时同步至 MySQL"
- **问题**：Oracle 没有 binlog（binlog 属 MySQL）。面试官一问"Oracle 的 binlog 怎么开的"就崩
- **证据**：领域常识；实测真实机制为 Oracle 物化视图（FAST REFRESH）
- **改写建议**："Oracle 侧基于物化视图（FAST REFRESH，依赖物化视图日志）获取增量变更，经 Kafka 投递、消费端幂等落库 MySQL；MySQL 侧订阅 binlog 做双向比对校验"
```

### 规则
- 每条必须给：编号、严重度、可验证性、类型编号、原文、问题、**可直接替换的改写文案**
- 改写**不得新增事实**（只能修正表述、补口径、降级夸大词、调整结构）
- "无法验证"的表述标为 `仅叙述`，只给话术建议，**不判编造**

## 二、薪资推荐 → `03_薪资建议.md`

### 输入
`jd.json`（含薪资区间）、`resume.json`、`02_复盘报告.md` 的总评、用户提供的城市/目标区间

### 铁律
> **只给区间，不给单点值。每项依据必须写出来源。不得输出无出处的市场数据。**

### 推理链（逐项列出，缺一不可）

| 步骤 | 内容 | 本次示例 |
|---|---|---|
| 1 | JD 区间 | 20K–35K |
| 2 | 年限/资历定位 | 12 年经验 → 落在区间上半段 |
| 3 | 能力匹配度（来自复盘） | 加权 3.8/5，核心维度达标、有 2 个缺口 |
| 4 | 城市系数 | 需用户确认；缺失时声明"未考虑城市差异" |
| 5 | 风险折扣 | 两年三跳 + 两段空窗 → 折价 |
| 6 | 结论区间 | 26K–30K，中位偏上取 28K |

### 输出附加内容
- **报价策略**：首报多少、如何应对压价、底线在哪
- **不确定性声明**：哪些因素无法评估（市场供需、公司预算弹性、竞争者情况）
- **依据声明**：明确写出"本建议不含实时市场数据，仅基于 JD 区间与资历推断"

## 三、简历改写 → `05_改后简历.html/.pdf`

### 输入
`resume.json`、`04_简历风险点.md`、用户对通用性/岗位定向的要求

### 铁律
1. **不新增无法自证的内容**（宁可少写，不写不确定的）
2. **默认不绑定单一岗位**（岗位定向是可选参数）
3. **保留全部真实事实**，只动表述、口径、结构、排序
4. **每处改动在改动说明中引用风险点编号**（`R-01`）

### 改写的六个动作
| 动作 | 说明 |
|---|---|
| 纠错 | 修正技术错误表述（R 类事实错误） |
| 补口径 | 给百分比加分子分母 |
| 降级 | "精通"降为"熟练"；无证据的"领先/极强"删除 |
| 补证据 | 把代码/依赖中真实存在的机制写进去 |
| 重排 | 按能力域组织技能栏，按时间倒序排项目 |
| 瘦身 | 压长段落为要点；无关细节降级 |

### 输出要求
- HTML：改动说明置于顶部，`@media print { display:none }`，不进 PDF
- 打印：A4、无页眉页脚、标题不孤立页底（`page-break-after: avoid`）
- **人工闸门**：先出 HTML，**等用户确认后**才导出 PDF
