# 风险与对策

## 1. 技术风险

| # | 风险 | 影响 | 对策 | 阶段 |
|---|---|---|---|---|
| T1 | **薪资建议不可信** | 损害信任，且可能误导用户报价 | 只给区间 + 强制推理链 + 依据声明；无出处数据一律不输出；无数据时只给"相对 JD 区间的位置" | P3 |
| T2 | **评分漂移** | 同一输入两次跑分不一样，无法验收 | 固定 rubric + 分档锚点 + 温度固定 + 抽样两次取均值；验收阀值 ≤ 0.3 | P3 |
| T3 | **简历解析失败** | 整条链跑不起来 | 多级降级：pdftotext → LibreOffice → 轻量内置解析 → 用户粘贴 | P1 |
| T4 | **模型调用成本/时长** | 用户体验差、费用高 | 轮次可配（默认 3）、追加上限 3 层、L0/L1 结果缓存、阶段断点续跑 | P2 |
| T5 | **长上下文退化** | 后期轮次质量下降、出现幻觉 | 每轮独立落盘、评估按轮分次调用、只传必要上下文 | P2/P3 |
| T6 | **验真误判** | 把"无法验证"当"造假"，冤枉用户 | 四档判决 + 可验证性分级 + 每条结论附可复现命令 | P4 |
| T7 | **仓库状态不一致** | 读错分支/未提交改动导致误判 | 记录并展示当前分支与 HEAD commit；只读；结论标注取证时点 | P4 |

## 2. 产品风险

| # | 风险 | 说明 | 对策 |
|---|---|---|---|
| P1 | 赛道拥挤 | 牛客/面试鸭/大量 GPTs 都在做模拟面试 | 主打验真层与闭环一致性，不做"泛模拟面试" |
| P2 | 复购极低 | 拿到 offer 就不再需要 | 定位为工具而非订阅；不投入产品化资源 |
| P3 | 获客成本高 | 求职者流量贵且流动 | 开源 + 技术影响力分发，不做投放 |
| P4 | 客单价低 | 单次几十元 | 不以此为目标收入 |
| P5 | 被当成"作弊工具" | 雇主反感 AI 代写经历 | 明确产品宣言：**只让真实经历表达准确，不制造经历** |

## 3. 合规与伦理边界（红线）

| 红线 | 具体要求 |
|---|---|
| 不伪造经历 | Skill 不得生成用户没做过的项目、职责、数字 |
| 不外传数据 | 代码与业务数据不出本地；产物默认落用户工作区 |
| 不伪装身份 | 面试对话 agent 只在演练场景中扮演，不用于真实面试中的实时提词 |
| 薪资不给虚假市场数据 | 宁可不给，不编造 |
| 保留人工闸门 | 简历类不可逆变更（导出 PDF）必须先经用户确认 |

## 4. 质量保障

| 手段 | 做法 |
|---|---|
| 回归集 | 3 份含已知埋雷的测试简历（含编造、数字不实、张冠李戴） |
| 回归方式 | 每次改 prompt / rubric 后跑回归集，检查编造检出率 ≥ 80% |
| 一致性检查 | 脚本校验五件套的风险点编号引用闭环（100%） |
| 人工抽检 | 每 10 次运行抽 1 次人工核对总评合理性 |
