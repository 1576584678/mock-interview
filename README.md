# mock-interview · 模拟面试官（DSH Skill）

> 输入一份**简历** + 一份 **JD**（可选附加**代码仓库路径**），输出一套可直接用于面试准备的**五件套**。

不是又一个"AI 陪你聊天模拟面试"。核心差异只有一句话：

> **大多数模拟面试产品只有简历和 JD 两个输入；这里有第三个——可被机器验证的代码仓库。**

本次真实跑通的例子里，靠交叉验真抓出的是这类问题：

| 简历原话 | 代码/事实 | 后果 |
|---|---|---|
| 累计输出 150 次提交 | git 实测 148（作者维度） | 数字不实 |
| Oracle 用 Binlog + Kafka 同步 | Oracle 根本没有 binlog | **技术性硬伤，一票否决级** |
| 基于 Redis 队列 + 异步任务调度 | 代码里是 List 轮询消费 | 追问即崩 |
| 引入业务指纹判重/复活机制 | 代码里不存在该机制 | **编造** |
| 111 个单元测试 | 实测 140 处 `@Test` | 数字过时 |

这五条中的任何一条被面试官戳穿，整份简历的可信度都会连带受损。

## 一、产出五件套

| # | 产物 | 内容 |
|---|---|---|
| 1 | `01_面试对话实录.md` | 面试官 / 求职者双 agent 多轮对话，含追问链、追问透、候选人失误点标记 |
| 2 | `02_复盘报告.md` | 逐题评分（固定 rubric）+ 追追问链评估 + 雷区命中 + 编造检测 + 总评与建议 |
| 3 | `03_薪资建议.md` | 期望薪资**区间** + 完整推理链 + 依据声明（不给单点值，不给无出处的市场数据） |
| 4 | `04_简历风险点.md` | 风险清单（严重度分级）+ 可验证性分级 + 逐条改写建议 |
| 5 | `05_改后简历.html/.pdf` | 修复版简历（保留原事实，只修错误表述、口径、措辞与结构）|

五件套之间存在**一致性约束**：第 4 份里每一条风险点都有编号，第 1 份的对话、第 2 份的评分、第 5 份的改动都必须能回溯到同一个编号。

## 二、快速开始（在 DSH 中使用）

```
@简历.pdf
这是 JD：<粘贴岗位描述>
帮我模拟面试，代码在 C:\project\xxx
```

Skill 被触发后会依次执行：输入归一化 → JD 维度抽取 → 证据验真 → 多维面试演练 → 评估与产出。

## 五、硬约束（不可协商）

1. **不编造**。任何未在简历、JD 或代码证据中出现的事实，不得写进任何产物。
2. **薪资只给区间**，必须附推理链与依据声明；不得输出"我查到的市场均价是 X"这类无出处的数据。
3. **评分必须可复现**。同一输入两次运行的加权总分偏差应 ≤ 0.3，超出则视为 rubric 失效。
4. **合规**。代码与业务数据不外传；所有产物默认落在用户本地工作区。
5. **不美化经历**。Skill 的职责是"让真实经历表达准确、匹配岗位"，不是"让候选人看起来更强"。
