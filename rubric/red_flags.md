# 雷区与编造检测规则

> 评审 agent 与验真脚本共用本文件。每条规则给编号，便于在产物中引用。

## 1. 编造类（F 系列）—— 最严重

| 编号 | 规则 | 检测方式 |
|---|---|---|
| F-01 | 描述了不存在于项目中的机制/模块 | 机制名或关键标识在代码中搜不到 → 与事实不符 |
| F-02 | 给出了无法自证的性能数字且无口径 | 追问"分子分母是什么"时答不上 |
| F-03 | 把团队成果描述为个人主导 | 与简历中角色表述、证据链矛盾 |
| F-04 | 引用了不存在的技术能力（如"Oracle 的 binlog"） | 领域常识即可判定 |
| F-05 | 回答中出现了简历里没有、且无法自证的经历 | 交叉比对简历文本 |

**处置**：F 类命中 → 该题直接 1 分；若在简历原文中出现 → 风险点严重度 🔴 一票否决。

## 2. 张冠李戴类（M 系列）

| 编号 | 规则 | 典型案例 |
|---|---|---|
| M-01 | 组件用错技术栈 | "Oracle 用 binlog 同步"（binlog 属 MySQL） |
| M-02 | 模型用错并发语义 | "RabbitMQ 的消费并发等于分区数"（Rabbit 无分区） |
| M-03 | 配置默认值说错 | "Resilience4j 默认 60 秒自动半开" |
| M-04 | 作用域说错 | "熔断按承运商单独配置"（实为平台级统一挂在拦截器层） |
| M-05 | 方向说反 | "先写预扣流水再扣 Redis 会导致少卖"（实为超卖的镜像问题） |

**处置**：该题最高 2 分；简历原文中出现 → 🟠 高。

## 3. 表述注水类（E 系列）

| 编号 | 规则 | 示例 |
|---|---|---|
| E-01 | "精通"密集出现（≥ 5 处） | 面试官会逐项验货，一处崩全线失信 |
| E-02 | 无口径的百分比 | "99.98%" 未说分子分母 |
| E-03 | 把弱保证说成强保证 | Redis List 轮询说成"消息队列" |
| E-04 | 用"主导/负责"描述参与级工作 | 无法回答"当时团队几个人" |
| E-05 | 数字与事实不符（过时或夸大） | "150 次提交" vs 实测 148 |

**处置**：🟡 中；建议改写 + 提前准备口径话术。

## 4. 时间线类（T 系列）

| 编号 | 规则 | 检测方式 |
|---|---|---|
| T-01 | 存在空窗期且无解释 | 时间线抽取后自动检出 |
| T-02 | 两段空窗用同一理由解释 | 面试官会识破（本轮实录已出现） |
| T-03 | 任职时间与项目时间矛盾 | 交叉比对 |
| T-04 | 跳槽频率异常（如"两年三跳"） | 统计任职时长 |

**处置**：🟡 中；必须准备**差异化**的真实解释。

## 5. 面试现场类（I 系列）

| 编号 | 规则 | 说明 |
|---|---|---|
| I-01 | 答不住时靠猜而不示弱 | 面试官对"猜"的容忍度远低于"不知道 + 推理" |
| I-02 | 没有反问环节 | 直接减分（软技能维度） |
| I-03 | 主动暴露与岗位无关的风险（如"心思在副业"） | 需要一句话卸掉 |
| I-04 | 薪资谈判先报底线 | 应先问预算或报区间上限 |
| I-05 | 被指出错误后过度辩解 | 正确做法：承认 + 更正 + 给正确版本 |

## 6. 岗位缺口类（G 系列）

| 编号 | 规则 | 处置 |
|---|---|---|
| G-01 | JD 的硬性要求中有明显空白 | 列入风险点，准备"如何快速补齐"的回答 |
| G-02 | 加分项完全无经验 | 诚实说明 + 展示相邻经验的可迁移性 |
| G-03 | 业务领域无经验（如 WMS 作业侧） | **绝不编造**，用相邻能力做迁移论证 |

---

## 附：检测优先级

```
F（编造）> M（张冠李戴）> G（岗位缺口）> E（注水）> T（时间线）> I（现场）
```

理由：F/M 会摧毁可信度；G 决定能不能过；E/T 影响印象；I 只在边缘局定胜负。
