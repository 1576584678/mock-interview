# mock-interview · 模拟面试官（DSH Skill）

> 输入一份**简历** + 一份 **JD**（可选附加**代码仓库路径**），输出一套可直接用于面试准备的**五件套**。

不是又一个"AI 陪你聊天模拟面试"。核心差异只有一句话：

> **大多数模拟面试产品只有简历和 JD 两个输入；这里有第三个——可被机器验证的代码仓库。**

本次真实跑通的例子里（简历 × `richinfo-qydn-server` / `面试教练`），靠交叉验真抓出的是这类问题：

| 简历原话 | 代码/事实 | 面试可见性 | 严重度 |
|---|---|---|---|
| Oracle 用 Binlog + Kafka 同步 | Oracle 根本没有 binlog | **当场可判**（常识） | 🔴 必改 |
| 基于 Redis 队列 + 异步任务调度 | 代码里只有 List 原子追加 + 范围读取，没有阻塞消费语义 | 追问可判 | 🟠 必须准备 |
| 99.98% / 95% 等百分比 | 简历没写分子分母与统计周期 | 追问可判 | 🟠 必须准备 |
| 累计输出 150 次提交 | git 实测 **148**（作者维度） | 需材料才可判 | 🟡 改成真实数字 |
| 111 个单元测试 | 精确实测 **138** 处 `@Test` | 需材料才可判 | ⚪ 改成真实数字 |

**这里有一条刻意设计的判断**：后两行"面试官看不到的东西"**不叫作假**。
代码里搜不到某机制 ≠ 你在面试里说了不存在的东西——所以严重度按**面试可见性**分级，
`is_fabrication` 只可能由面试实录（P3）置位。详见 [`docs/EVIDENCE.md`](docs/EVIDENCE.md)。

> 📄 完整的可运行示例（输入 + 五件套产物）见 [`examples/minimal/`](examples/minimal/)。

## 一、产出五件套

| # | 产物 | 内容 |
|---|---|---|
| 1 | `01_面试对话实录.md` | 面试官 / 求职者双 agent 多轮对话，含追问链、追问透、候选人失误点标记 |
| 2 | `02_复盘报告.md` | 逐题评分（固定 rubric）+ 追追问链评估 + 雷区命中 + 编造检测 + 总评与建议 |
| 3 | `03_薪资建议.md` | 期望薪资**区间** + 完整推理链 + 依据声明（不给单点值，不给无出处的市场数据） |
| 4 | `04_简历风险点.md` | 风险清单（严重度分级）+ 可验证性分级 + 逐条改写建议 |
| 5 | `05_改后简历.html/.pdf` | 修复版简历（保留原事实，只修错误表述、口径、措辞与结构）|

五件套之间存在**一致性约束**：第 4 份里每一条风险点都有编号，第 1 份的对话、第 2 份的评分、第 5 份的改动都必须能回溯到同一个编号。

## 二、快速开始

**首次使用看 [`INSTALL.md`](INSTALL.md)**（3 步跑通）。最省事的验证方式：

```bash
git clone https://github.com/1576584678/mock-interview.git
cd mock-interview
python tools/selfcheck.py      # 环境自检 + 跑一遍内置回归（163 项 + 3 份回归简历 + SKILL.md 触发词）
```

在 DSH 中使用：

```
@简历.pdf
这是 JD：<粘贴岗位描述>
帮我模拟面试，代码在 C:\project\xxx
```

Skill 被触发后会依次执行：输入归一化 → JD 维度抽取 → 多轮面试演练 → 评估产出 → 代码验真。

## 五、硬约束（不可协商）

1. **不编造**。任何未在简历、JD 或代码证据中出现的事实，不得写进任何产物。
2. **薪资只给区间**，必须附推理链与依据声明；不得输出"我查到的市场均价是 X"这类无出处的数据。
3. **评分必须可复现**。同一输入两次运行的加权总分偏差应 ≤ 0.3，超出则视为 rubric 失效。
4. **合规**。代码与业务数据不外传；所有产物默认落在用户本地工作区。
5. **不美化经历**。Skill 的职责是"让真实经历表达准确、匹配岗位"，不是"让候选人看起来更强"。
