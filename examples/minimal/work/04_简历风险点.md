**R-02**｜🟠 能力缺口｜来源：评审 agent 产出（已通过「不新增数字」校验）

> 不要在简历里补写「熔断经验」。准备迁移话术：说明你做过的是消费失败进死信队列 + 人工补偿入口这类兜底，讲清熔断、限流、降级的区别与各自触发条件，并主动声明熔断是你尚未在生产落地的部分（盲区），给出上手路径。
>
> 备注：JD 硬性要求缺失项；只修话术口径，不新增经历。

追问准备：没有 熔断 经验时，用相邻能力做迁移论证（说清哪些能做、哪些是盲区）

**R-03**｜🟠 能力缺口｜来源：评审 agent 产出（已通过「不新增数字」校验）

> 同理不补写「限流经验」。可迁移的相邻能力是缓存穿透处理与失败补偿链路；话术里明确「限流我在生产上没有落地，但能说清网关/单机限流的实现位置与选型差异」，把不会的点讲成边界而不是空白。
>
> 备注：JD 硬性要求缺失项；只降口径、补边界。

追问准备：没有 限流 经验时，用相邻能力做迁移论证（说清哪些能做、哪些是盲区）

**R-04**｜🟠 能力缺口｜来源：评审 agent 产出（已通过「不新增数字」校验）

> 不把死信队列与人工补偿包装成「降级」。话术：「降级我理解为在依赖不可用或超时率上升时切换到兜底逻辑；我在消息链路里做过的是消费失败隔离与人工补偿，属于故障兜底的一种，但严格意义的接口自动降级我没有负责过。」

> 备注：避免把兜底改写成降级，防止被追问成本与失败路径时崩。

追问准备：没有 降级 经验时，用相邻能力做迁移论证（说清哪些能做、哪些是盲区）

> 备注：口径缺失类；Topic 数量不是加分项。

> 「累计处理消息 1.2 亿条」要么补齐真实口径（分子是生产端投递还是消费成功、统计周期多长、口径来源），要么改成定性：「基于 RocketMQ 事务消息保证『订单下发 → 库存扣减』最终一致，消费失败进入死信队列并有人工补偿入口」。无法自证时选后者。
