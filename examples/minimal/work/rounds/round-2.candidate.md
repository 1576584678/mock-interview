## 三、核心准则（违反即视为演练失败）

1. **只用上面的事实作答。** 简历没写、代码里没有的经历，一律不能说。
2. **不确定时必须示弱，不许猜。** 正确姿态：
   > "这块我只在设计层面考虑过，没有生产落地经验。我的理解是……如果要我用，我会先验证……"
   错误姿态：编一个听起来合理的机制。
3. **数字必须带口径。** 说百分比时主动给分子分母。
   > ❌ "准确率 99.98%"
   > ✅ "对账一致率 99.98%，口径是日终对账中一致行数除以比对总行数"
4. **超出能力边界时诚实。** 例如没有 RocketMQ / TiDB / MyCAT / WMS 作业侧经验——直接说，
   并给相邻能力做迁移论证，**绝不编造**。
5. **被指出错误时**：承认 → 更正 → 给出正确版本 → 一句话收尾。不辩解、不找借口。
6. **答案结构**：结论先行 → 机制 → 取舍 → 边界。主答 80–150 字，追问回答 40–100 字（口语长度）。

## 四、本轮问题（**请逐题作答，并逐层回答面试官的追问链**）

```
### Q1｜维度：分布式数据库　目标风险：R-06
问题：你上一轮自己更正了一个关键点：事务消息的本地事务只能覆盖单库，跨库就断了。现在把场景坐实——如果出库单库和库存库拆成两个物理库，沿用「订单下发 → 库存扣减」这条链路，请你给出你会真正落地的最终一致方案：本地事务的边界放在哪、跨库这一步靠什么补偿、失败之后靠什么发现。
面试官准备的追问链（请**逐层**回答，共 3 层）：
  1. 你简历写消费失败进死信队列、人工补偿入口日均处理 30 余笔。这 30 余笔的分子、分母分别是什么——是死信条数还是被人工处理过的工单数？统计周期多长，重投成功的那部分算不算在内？
  2. 本地消息表、事务消息、TCC、对账补偿这四种，跨库时你会选哪一种？请说出你排掉另外三种的具体代价，而不是优劣形容词。
  3. 极端情况：对账发现某笔出库单库存已经扣了、单据却没落库，而消息已经被消费端 ack。你的定位链路是什么，先查哪张表、靠什么幂等键把重复扣减挡住？

### Q2｜维度：分布式数据库
问题：你明确说了分库分表只在测试环境做过 ShardingSphere 验证、TiDB 只是了解过没有实际使用。那我按迁移评估来问：如果出库单表从单库迁到分库分表或者 TiDB，你上一轮讲的那套「两段查询 + 批量填充」会在哪些环节直接失效？跨分片的事务、唯一键幂等和全局唯一 ID，你打算怎么补？
面试官准备的追问链（请**逐层**回答，共 3 层）：
  1. 分片键你会选什么？为什么不是面单号或者承运商，选了之后哪些查询会退化成跨全部分片的广播查询？
  2. 分布式事务你更倾向 Seata AT 还是本地消息表加对账？说出这两个方案落在出库链路上的具体代价差异。
  3. 如果 TiDB 的乐观事务在冲突高发时不断重试，出库单创建这条链路会出现什么现象？你先看哪个指标能发现它？

### Q3｜维度：稳定性　目标风险：R-05
问题：大促场景换一个切面：压测目标是 300 单/秒，出库单创建是写链路，削峰只能压到 MQ 上。你的 Topic 是怎么划分的——简历里写了 Kafka 有「3 个 Topic」的生产与消费，先说清这 3 个 Topic 分别承载什么业务、这个「3」是怎么数出来的；再说大促期间出现消费积压时你的限流与扩容动作。
面试官准备的追问链（请**逐层**回答，共 3 层）：
  1. 这 3 个 Topic 的分子、分母和统计周期分别是什么？是当前存活 Topic、还是包含已下线 Topic，是否含测试环境的 Topic？
  2. 消费积压时你按什么指标触发扩容：Lag 条数、单条消费耗时还是 Broker 堆积量？阈值怎么定，扩容之后消费端幂等还成立吗？
  3. 如果限流把出库单创建从 300 单/秒压到 150 单/秒，多出来的请求在业务上表现为什么？你怎么避免用户重复下单。

### Q4｜维度：JVM　目标风险：R-07
问题：你上一轮如实说了没有独立做过 JVM 层的排查，那我不让你编案例，换成你简历里确实有的基础来问：出库单服务跑在 K8s 上、Java 17。假设容器 limit 是 2C4G，跑一段时间后 Pod 频繁被 OOMKilled，但你看到的 JVM 堆水位只有 60%。请讲清你的判断顺序，以及 Java 17 下堆参数与容器 limit 对不上的时候，会在哪一步失效。
面试官准备的追问链（请**逐层**回答，共 3 层）：
  1. Java 17 上 G1 与 ZGC 你分别会在什么负载特征下选？说出你放弃另一个的具体代价，而不是「ZGC 停顿低」这种结论。
  2. 容器里 MaxRAMPercentage 和 -Xmx 同时配了会以哪个为准？配置冲突时现象是什么，你从启动日志的哪一行确认？
  3. 如果确认是直接内存或 Netty 那类堆外占用涨上去，你的定位手段是什么，为什么 jmap 堆快照看不出来？

### Q5｜维度：稳定性
问题：收尾换到稳定性治理：出库链路的兜底。如果大促期间面单回传的下游承运商接口整体超时，而出库单已经创建、波次也已经分配，这时候你按什么顺序做保护动作？事后靠什么判断可以恢复，并按什么节奏放量？
面试官准备的追问链（请**逐层**回答，共 3 层）：
  1. 降级期间面单没有回传的单据怎么标记？会不会出现重复回传，你靠什么键做幂等？
  2. 恢复后堆积的补偿任务和实时流量会抢同一个下游，你怎么排优先级，会不会把下游再打挂一次？
  3. 这套预案你实际演练过吗？如果没有演练过，你凭什么认为它在真故障时能生效？

```

- `candidate_questions` 是结尾反问环节的 2–3 个问题，要体现对岗位/团队技术现状/个人成长的思考。

写完后**只回复 3 行以内的摘要**（轮次、题数、有无示弱项），不要把 JSON 全文回给调用方。
