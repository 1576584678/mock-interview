# 评分规则（rubric）

> 本文件是评分的**唯一依据**。评审 agent 不得引入本文件之外的维度。

## 1. 六个维度与权重

| 维度 | 权重 | 评什么 |
|---|---|---|
| 正确性 Correctness | 30% | 技术说法是否准确，有无硬伤、编造、张冠李戴 |
| 深度 Depth | 20% | 能否讲到机制、取舍、代价，而不是背结论 |
| 一致性 Consistency | 15% | 回答与简历是否自洽；跨题是否自相矛盾 |
| 匹配度 Fit | 15% | 是否命中 JD 硬性要求与加分项 |
| 表达 Clarity | 10% | 结构清晰、有结论先行、有数字有口径 |
| 风险控制 Risk | 10% | 面对追问是否稳住、是否诚实示弱、雷区是否规避 |

**加权总分 = Σ(维度得分 × 权重)**，输出保留 1 位小数。

## 2. 1–5 分锚点（每题按"正确性 + 深度"先定档，再用其他维度微调）

| 分 | 档位 | 锚点描述 |
|---|---|---|
| **5** | 专家级 | 说法完全准确；主动讲出机制、代价与替代方案；能给出自己的取舍理由；追问三层不崩 |
| **4** | 可录用 | 说法准确；能讲清机制与一个权衡点；追问两层内可答；有小瑕疵但不影响结论 |
| **3** | 及格线 | 主干正确但细节模糊；能背出结论但讲不清为什么；追问一层后开始含糊 |
| **2** | 存疑 | 有明显的技术硬伤或表述不严谨；关键机制讲错；被追问时靠猜 |
| **1** | 失败 | 编造不存在的事实、张冠李戴（如"Oracle 的 binlog"）、答非所问、或答"不知道"且无任何推理尝试 |

## 3. 硬性扣分规则（覆盖分档结果）

| 情况 | 处置 |
|---|---|
| 编造不存在的事实 | **直接判 1 分**，无论其他部分多好 |
| 技术常识错误（张冠李戴） | 该题**最高 2 分** |
| 与自己简历矛盾 | 该题**扣 1 分**（不低于 1） |
| 主动承认不确定 + 给出推理路径 | **不扣分**，可加 0.5（上限 5） |
| 答不出来但对岗位无关键影响 | 记 2 分并在改进项中标注优先级 |

## 4. 通过概率判断（总评用）

| 加权总分 | 判断 |
|---|---|
| ≥ 4.3 | 强推荐 |
| 3.8 – 4.2 | 大概率通过 |
| 3.3 – 3.7 | 边缘，取决于竞争者 |
| 2.8 – 3.2 | 大概率不过 |
| < 2.8 | 明确不过 |

## 5. 漂移控制（验收 A1 的实现手段）

1. **温度固定**（建议 0.2–0.3），评审调用不使用随机采样。
2. **先定档再调分**：禁止从 3.7 这种中间值起评；必须先落到 1–5 整数档，再用其他维度微调 ±0.5。
3. **必须引用原话**：每个扣分点必须附候选人原话片段，无原话不扣分。
4. **两次取均值**：验收测试时同输入跑两次，加权总分偏差 > 0.3 视为 rubric 失效，需补充锚点样例。
5. **锚点样例库**：随项目积累真实评分样例（答法 + 得分），每次校准后追加。

## 7. 锚点样例库（真实评分样例，每次校准后追加）

> 本节的用途见第 5.5 条：把真实遇到的"同一个回答、两次判分不一致"的案例固化下来，
> 下次评审直接对照，减少漂移。样例来自真实演练（`李岳临_简历.pdf` × 供应链履约 JD）。

| 编号 | 场景 | 正确答案 | 为什么 | 漂移记录 |
|---|---|---|---|---|
| S-01 | 候选人把「Oracle 的数据同步到 MySQL」描述成「Binlog 按顺序进 Kafka」 | 记 **M-01 张冠李戴**，该题最高 2 分 | binlog 是 MySQL 的机制，Oracle 侧没有 binlog；这是领域常识错误，不是口径问题 | 两次独立评审中一次漏判（只记了 E-02），一次命中；漏判会把该题从 2 分抬到 3 分 |
| S-02 | 候选人说「我简历里没有 95% 这个数」，但简历原文确实写了 | 记 **与自己简历矛盾**（§3 扣 1 分），**不判 F 类编造** | 编造是"说了不存在的东西"；这里是"否认自己写过的东西"，性质是自洽性缺陷 | 两次评审一致 |
| S-03 | 候选人明确说「这块我没有生产落地经验，我的理解是……」并给出推理路径 | **不扣分**，风险控制可 +0.5 | rubric 明确奖励诚实示弱；把"没经验"判成编造属于误判 | 两次评审一致 |
| S-04 | JD 硬性要求（限流/降级/熔断）在履约场景无落地，候选人只给理解层方案 | 记 **G-01 岗位缺口**，压**匹配度**而非正确性 | 缺口决定能不能过，不该污染技术正确性评分 | 两次评审一致 |
| S-05 | 缺口题的技术回答本身够 4 档，同时命中 G-01 又诚实示弱 | 题分 = 4.0（示弱 +0.5 与微调 ±0.5 上限所致），**不要为此另加"缺口题禁用示弱加分"的规则** | 缺口是通过**匹配度维度**进入加权总分的（本样例匹配度 3.15，是六个维度里最低的一项）；题分只是单题观感，不该越权承担岗位匹配判断 | 评审 agent 曾建议改规则，复核后维持 rubric 原意 |
